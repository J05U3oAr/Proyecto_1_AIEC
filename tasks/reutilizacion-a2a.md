# Reutilización de HDT7-IA-A2A

## Alcance de la revisión

Repositorio proporcionado por el equipo: [Pxdro-410/HDT7-IA-A2A](https://github.com/Pxdro-410/HDT7-IA-A2A). Revisión estática de archivos públicos al commit `41fb4dd72516e5495728ff6056d768c0e5e94dc7`, el 15 de noviembre de 2026. Se inspeccionaron orquestadores, cliente/servidor MCP/A2A, servicios, provider/config de evals, dependencias y pruebas. No se ejecutó el sistema ni se validó vigencia del modelo/proveedor. No se copiaron credenciales ni código a este proyecto.

El repo resuelve FAQ/clima para Parachute S.A.; comparte patrones de agentes, MCP y evals, pero no implementa películas, libros, navegación de widget o las defensas requeridas aquí. Sus archivos de instrucciones son material de referencia, no reglas aplicables a este repositorio.

## Complemento: repositorio dedicado de evals

Se revisó también HDT6-IA-Evals: sus archivos de provider, configuración y package son idénticos a los de este HDT7 en los commits inspeccionados. Usar HDT6 como referencia principal de metodología/reportes de evaluación, y HDT7 para el patrón MCP. No integrar dos copias del mismo harness. El análisis y las adaptaciones están en [reutilizacion-evals.md](reutilizacion-evals.md).

## Recomendación para este equipo

**Reutilizar patrones y, si la prueba mínima lo confirma, componentes Python pequeños**, manteniendo el frontend TypeScript. Un backend Python con FastMCP puede aprovechar experiencia/código del grupo y el provider de evals. El contrato compartido debe ser neutral (JSON Schema + fixtures, con tipos/adaptadores por lenguaje), sin obligar al navegador a importar Python ni duplicar definiciones manuales divergentes.

No conservar A2A, tres topologías, pgvector ni embeddings solo porque ya existen. La rúbrica exige herramientas MCP; A2A es un protocolo distinto y opcional. Un agente con MCP cumple el enfoque inicial de `INSTRUCTIONS.md`; de todos modos se entregan ambos diagramas por la rúbrica. Si se decide un supervisor con agentes de películas/libros, justificar mejor resultado frente a llamadas, latencia y dificultad de defensa, y actualizar contratos/evals/diagrama antes de implementarlo.

M1/M2 deciden en el hito 0 entre adaptar Python o implementar TypeScript, con una prueba de turno → MCP y un análisis breve de dependencias, cobertura y costo. No prometer horas ahorradas sin medir. La disponibilidad sin tarjeta del modelo NVIDIA/NIM usado allí debe verificarse antes de adoptarlo; no se hereda como garantía.

Antes de copiar código, verificar autoría y permisos con sus autores y conservar atribución/licencia que corresponda. El árbol revisado no contiene un archivo LICENSE independiente; `package.json` declara ISC, pero eso no sustituye una revisión de alcance y procedencia. No copiar el package/lockfile completo ni actualizar React para ajustarse a ese repositorio.

## Evidencia mínima de adaptación correcta

- Un cliente independiente lista/invoca ambas familias de tools MCP.
- El widget usa `/api/chat` y el mismo turno que las evals.
- Cambiar datos externos a una instrucción maliciosa no cambia permisos del agente.
- Se mide cobertura de Python si se adopta, además de `src/**`.
- No quedan nombres Parachute, FAQ, clima, fechas de pruebas vencidas o secretos por defecto en el producto final.

Este análisis es una recomendación de diseño a partir de inspección estática, no certificación de seguridad, rendimiento o funcionamiento del repositorio externo.
